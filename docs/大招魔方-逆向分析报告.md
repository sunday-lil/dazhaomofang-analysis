## 3. 整体架构

### 3.1 应用生命周期（dist/main.js）

```js
App({
  setup()            -> pc-electron-core 启动
  indexLaunched()    -> business/init 初始化
  loggedIn()         -> 课前 BV 容器初始化 + 热更新启动
  beforeClassEnter() -> 中止热更新
  classExited()      -> 退课
  updateTriggered()  -> 触发更新
  beforeAppQuit()    -> 热更新收尾（退出时 spawn bytecode.exe 应用更新）
})
```

### 3.2 进程通信模型

- **主进程** `pc-electron-core`：窗口管理（BrowserWindow/BrowserView 容器）、下载、热更新、日志、AI 模型管理
- **渲染层** 通过 `contextBridge` 注入 `window.EV2Client`（v2，课前/课中 BV 页面）与 ZCefClient（v1，旧版页面）
- **事件总线**：`__ELECTRON_EVENTS_CENTER__` 跨窗口消息（支持 NORMAL / RESPONSIVE 两种模式，RESPONSIVE 超时 3s）
- **H5 插件通道**：`H5_PLUGIN_ACTION_CHANNEL` / `H5_PLUGIN_ACTION_RETURN`
- **课前 BV 容器**（`PC_BEFORECLASS_V2`）承载课件、Cocos 练习本、AI 评测等子容器

### 3.3 热更新流程

`hotUpdateManager`：登录后 `toUpdate()` → 下载差分包 → 退出时 spawn `bytecode.exe --resourcesPath=<resources>` 静默应用更新。

## 12. 隐私与安全观察

> 以下为基于静态分析的**研究性观察**（非漏洞利用，未做任何攻击验证），供安全研究者与用户参考。

1. **AI 摄像头分析**：客户端内置专注力/离席/坐姿/表情/手势/距离检测。检测在**本地**完成（MNN 离线推理），但 SDK 返回结构含 `is_upload` 标记，说明在满足内部策略条件时**学生摄像头画面可能被上传**（文件命名含 roomid/lessonid/userid/时间戳）。上课弹窗授权、策略开关由服务端下发（`enable_mixroom_ai`、`getAIConfig`）。
2. **代理请求绕过同源策略**：`EV2HttpRequest` / `EV2CoreHttpRequest` 允许任意网页经主进程发起任意 URL 请求（白名单见 `CORE_DOMAIN` 校验与 `domainProxy` 规则替换）。
3. **高危 IPC**：`PCTrySpawn` / `PCTryExec` / `PCTryExecFile` 允许渲染层启动子进程。若任一加载的远程页面被 XSS，即可能形成 RCE 链（取决于主进程侧校验；`trySpawn` 失败时静默返回 true）。
4. **明文密钥**：AI 模型解密密钥、上传令牌、埋点 authKey 均硬编码于客户端，可被直接提取（见第 11 节）。
5. **崩溃与日志上报**：崩溃转储（CrashSender1403.exe → smt-upload）、行为日志（fmp-notice、zbklog、logmetric）多路上报，包含设备指纹（pcDevice）。
6. **模型加密下载**：AI 模型为加密下发，解密后落盘明文 .mnn。
7. **供应链提示**：sourcemap（`.map` 文件）随生产包发布，等于附带了可读源码，建议厂商在构建流程中剔除。
